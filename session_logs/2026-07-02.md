## 세션 (blind choice) — 요약
선택지 결과 숨김(blind choice)을 구현했다. 상황 카드의 선택지에서 결과(자원 델타)를 누르기 전엔 "?"로 감추고,
필요조건(needs)은 노출하며, 이번 런에 눌러본 선택지만 다음 대면 때 결과를 보여준다(학습). 런 한정 + 선택지 단위.

## 주요 변경
- `scripts/ui/UITheme.gd` — 공통 헬퍼 추가: `RES_KO`·`effect_hint`·`needs_bare`·`choice_text`(blind 라벨 로직 일원화, 지도·단면 공유).

- `scripts/ui/Map.gd` — 이동 중 상황 카드에 동일 적용. 로컬 중복 제거.
- `scripts/GameState.gd` — `run_seen_choices`(런 한정, 세이브 미포함) + `has_seen_choice`/`mark_choice_seen`. `begin_run_with`·`reset_save`에서 clear.
- `docs/design/SYOTOS_기획서_v0.1.md` §4.2 — blind choice 규칙 문단 추가.

## 결정 사항
- **기억 범위 = 런 한정**(사용자 결정): 다음 원정은 다시 백지 → 매 원정 첫 대면의 긴장 유지. 세이브 미포함.
- **식별 단위 = 선택지 단위**(사용자 결정): 실제 눌러본 선택지만 노출, 안 고른 건 여전히 "?". 키 = "event_id#idx".
- **상태를 GameState에 둔 이유**: 원래 ExpeditionRun(런 상태의 자리)이 맞지만 (1) 밸런스 세션이 ExpeditionRun.gd를 claim했고, (2) Expedition·Map은 별개 씬이라 런 상태 공유는 어차피 autoload 경유가 필요. 두 조건이 GameState를 실용적 자리로 만들었다.
- **동시 세션 커밋 분리**: 기획서·backlog가 밸런스 세션과 공유 파일이라, 같은 파일에 두 세션 변경이 공존했다. `git apply --cached`로 내 hunk만 부분 스테이징하고, 밸런스 세션이 이미 add해둔 파일들은 `git restore --staged`로 index에서 내려(워킹트리 보존) 커밋을 깨끗이 분리했다.

## 결정 사항
- **방향(사용자 결정): 보급 강화(거리 유지).** 2D 스윕상 `EDGE_LEN`이 지배적 손잡이(EDGE 5 유지 시 DESO 28까지 올려도 <1%)지만, 거리감(35걸음) 유지를 택함. → `EDGE_LEN` 5 고정하고 DESO 완화(걸음 수 불변, 후반 가속만 늦춤) + 후반 캐시 물로 도달성 확보.
- **DESO 30 선택 이유:** `leg 30+`에서만 2배 = 완주 마지막 5걸음 가혹 → 거리 곡선 철학 유지하며 벽만 낮춤. EDGE5·DESO30 = 생존탐욕 ~10%·무모 ~0.2%(스킬 격차 유지), 목표 10~20% 하한 안착. 폰 실플레이는 완벽 greedy보다 낮으니 시뮬 10%가 "희소"에 적절.
- **손잡이 `const`→`static var`:** 시뮬 `[3]`의 오랜 한계(코드 상수라 스윕 불가) 해소. 실제 로직 그대로 스윕하므로 시뮬이 정직(코드-사양 갈라짐 없음). 게임 동작 불변.
- **후반 캐시만 증량:** 후반 지속력↑ + 초반 긴장 유지("먼저 간 원정대 유품이 후반일수록 많다" 서사와 일치). 다만 후반 캐시는 도달한 소수만 밀어주므로 실효가 작아 → DESO를 주 조정축으로.

## 결정 사항
- **공유 컴포넌트 2개 신설**(중복 회피): 지도·단면이 같은 남기기/결과 UI를 필요로 함. Expedition의 남기기 100줄을 BequeathPanel로 이관하니 도착 화면도 간결해지고 지도도 재사용. core(ExpeditionRun)는 무변경 — 남기기 로직(can_leave/do_leave)이 이미 위치 무관.
