## 세션 5 (밤) — 모바일 UI 전면 재작성

### 요약
세션 4의 폰트만 키운 패스가 폰 세로에서 거의 티가 안 났다. 사용자 피드백으로 근본 원인 규명: **base 해상도가 1280 폭**이라
세로 화면에 1280 폭 레이아웃을 통째로 축소해 넣어 모든 게 작았던 것. 모바일 우선으로 base 교정 + UI 전면 재작성.

### 주요 변경
- `project.godot` `[display]` — `viewport_width` 1280→**600**(세로 논리폭=600 → 체감 ~2배), `window_*_override=1280x720`(데스크톱 창은 가로 유지).
  `default_font_size` 20→24(다이얼로그 등 기본 텍스트).
- `scripts/ui/UITheme.gd` — 전면 재작성. 모바일 타입 스케일(FS_DISPLAY/H1/H2/BODY/LABEL/SMALL/TINY), 색 팔레트(+PANEL/SCRIM),
  레이아웃 헬퍼: `build_column`(중앙 최대폭 컬럼), `make_card`(StyleBoxFlat 카드), `make_button`(풀폭 터치), `make_label`(자동 줄바꿈).
- `scripts/ui/Main.gd`·`Map.gd` — 컬럼 레이아웃 + 큰 타이틀 + 풀폭 버튼으로 재작성.
- `scripts/ui/SettingsPanel.gd` — 어두운 배경 + 가운데 **카드** + 풀폭 버튼.
- `scripts/ui/Expedition.gd` — 상단 HUD를 **반투명 배경 바**(자원 수치 FS_H1로 크게)로, 하단을 **큰 전진(주) + 보조 끝** 컬럼으로,
  상황/죽음 모달을 떠다니는 텍스트가 아니라 **카드**로. `_draw` 텍스트도 UITheme 크기.

### 결정 사항
- **base width = 세로 체감 크기의 단일 손잡이.** `canvas_items+expand` 에서 세로는 가로가 제약 축 → 논리 가로폭 = base width.
  가로/데스크톱은 세로 base 가 제약 축이라 영향 없음. 그래서 600으로 줄여 세로만 키움(가로 불변). 더 키우려면 이 숫자만 더 낮춘다.
- **중앙 최대폭 컬럼 패턴.** `MarginContainer→CenterContainer→VBox(min width 520)`. 세로폰(600폭)에선 거의 꽉, 가로(1280폭)에선 가운데 카드. 한 코드로 양쪽.
- **모달=카드.** 어두운 배경 위 떠다니는 텍스트 대신 둥근 패널(StyleBoxFlat) 위에. 가독성·집중 ↑. 웹 안전(셰이더 없음).
- **위계: 전진 강조, 끝 보조.** 코어 루프 동사(전진)는 크게, 드물게 쓰는 "남기고 죽기"는 낮고 흐리게. 모바일 엄지 동선.

### 검증
- `--import` + 타이틀 부팅 + (main_scene 임시 교체)expedition 부팅 + 웹 export 4종 모두 에러 0. make_card/HUD StyleBoxFlat 런타임 통과.
- 실제 세로 체감 크기·줄바꿈·터치감은 폰 브라우저 실기기 확인 필요(배포 + 강력 새로고침).

### 미해결 / 다음 할 일
- 폰 실기기 확인 후 base width(600)·타입 스케일 미세 조정(더 크게/작게는 viewport_width 또는 UITheme 한 곳).
- 버튼 chrome·팔레트는 기본 테마 유지 — backlog "그래픽/비주얼 전면 교체"에서 스타일박스·테마로.

## 세션 11 (낮) — 선택 반영 일반화 (명명 플래그)

## 세션 10 (낮) — 정체성 수정 (흔적 = '이전 원정대')

### 요약
사용자 로어 수정: 플레이어는 "과거의 나"를 따라가는 게 아니라 **원정대 총괄자 + 매 원정의 대장 역**이며, 매 원정은 *매번 다른 사람*이 간다(플레이어는 그 사실을 앎).
흔적(시드 + 자기 과거 런)을 남기고 받는 in-world 주체는 "이전/다음 원정대". choice-flags 세션 종료(685ea55) 후 파일을 claim 해 일괄 적용.

### 주요 변경
- 게임 텍스트: `Situations.gd` `past_flask`·로프 통과 카드 "과거의 내가" → "이전 원정대가", 남김 "다음 나에게" → "다음 원정대에게". `Expedition.gd` 남김 패널·죽음 문구 "미래의 나/다음 나" → "다음 원정대".
- 주석 정합화: `Expedition`·`TraceData`·`ExpeditionRun`·`GameState`·`Map`.
- 문서: `SYOTOS_기획서` §0/§1/§2/§3/§4/§5, `CLAUDE.md`·`README.md` 첫 문단. **중심 질문·제목의 메타 '미래의 나'는 유지.**
- 메모리 `syotos-identity-overseer` "적용됨"으로 갱신. (커밋 a438be6)

### 결정 사항
- **in-world 주체 = 원정대, 메타 '나' = 유지.** 물리적 흔적 주체는 다른 사람(이전/다음 원정대), 제목 의미 반전·중심 질문은 메타 층위(총괄자/플레이어 자리)라 그대로.
- **남김/받음 일관 적용.** 받는 쪽뿐 아니라 남기는 쪽도 "다음 원정대"로. (제목 테마 위해 남김 문구를 '미래의 나'로 되돌리려면 사용자 지시.)
- **거짓 태그 근거 미결.** 주체가 "다른 사람"이 되며 wordpool "거짓 없음(자기 자신이라)" 전제가 흔들림 → 기획서 §2/§3 ⚠️ 플래그만, wordpool 미수정. 거짓 태그 재도입 여부 사용자 결정 대기.

### 검증 / 동시 세션
- `--import` + 타이틀 부팅 에러 0(텍스트·주석 변경만). choice-flags 종료 확인 후 진행, 내 9개 파일만 커밋.

## 세션 12 (낮) — 흔적 줍기 효과

### 요약
"남김 한 번"의 짝. 이전 원정대가 남긴 자원 흔적(물통/식량/은신막)을 다음 원정대가 집어 보충 → 코어 루프(남김↔줍기)를 닫음.
흔적은 유한(uses ~3): 집을 때마다 소진, 0이면 사라짐. 여러 원정이 한 물통을 나눠 쓰다 마른다(사용자 "3회 정도").

### 주요 변경
- `scripts/core/TraceData.gd` — `uses` 필드(기본 0) + `PICKUP_USES`=3. to_dict/from_dict 직렬화.
- `scripts/core/Situations.gd` — `pickup_trace(info)` 줍기 카드(종류별 보충 물4/식3/은1, action="pickup", trace_kind).
- `scripts/core/ExpeditionRun.gd` — 생성자 `pickup_traces` 주입(`_traces`), step 에 흔적 leg 분기(랜드마크 다음, 일반 상황 전).
- `scripts/GameState.gd` — `pickup_traces_map()`(자원+uses>0, leg당 첫 흔적) + `use_trace(leg,kind)`(uses-1, 0이면 제거) + begin_run 주입.
- `scripts/ui/Expedition.gd` — `_on_choice` 가 action="pickup" → `use_trace`. `_commit_bequeath` 가 줍기형(WATER/FOOD/SHELTER)에 uses=3 부여.
- 기획서 §4.4(흔적 줍기) 추가. backlog "흔적 줍기 효과" 항목 완료 정리.

### 결정 사항
- **유한 사용(uses ~3), 1회 소비 아님.** 사용자 선택. 이전 원정대의 유산이 몇 대에 걸쳐 도움(self-async 정서) + 무한 보충 방지.
- **남겨두면 유지.** 줍지 않으면 uses 그대로 → 다음 원정대 몫(선택의 무게).
- **줍기 대상 = 자원 흔적만.** WATER/FOOD/SHELTER. BODY/MARK는 점만(정서), ROPE는 차단 다리(§4.1).
- **랜드마크 > 흔적 > 일반 상황 우선.** 흔적은 비-랜드마크 leg 에서 줍기 카드. core 순수성(주입 + use_trace).

### 검증
- `--import` + `-s`: leg6 흔적 → pickup 카드, 종류별 보충(물4/식3/은1), action·trace_kind 정확. main 부팅 에러 0.
- use_trace/pickup_traces_map(GameState)은 `-s` 불가라 코드 + ExpeditionRun 4인자 `-s` 로 검증. 실제 소진(3회→사라짐)은 폰 플레이로.
