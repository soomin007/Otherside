## 결정 사항
- **core/ui 분리를 타협 불가 원칙으로.** Be-the-Bee 의 engine/ui 분리를 Godot 에 이식 — core 는 순수
  데이터·로직, ui 는 렌더링. 흔적/위협이 "풀 수 있는 시스템 문제"가 되도록(기획서 의도).
- **세이브는 JSON 직렬화.** 웹 user://=IndexedDB 와 잘 맞고, 흔적 상태를 평범한 Dictionary 로 다루기 위함.
- **사양을 코드 데이터로 복사(Threats/WordPool).** 확정·유한·큐레이션된 목록이라 저위험·고가치. 기획서가 진실이므로 바뀌면 같이 갱신.
- **Phase 0 범위 = 인프라+아키텍처+루프 뼈대.** 게임플레이 본구현은 backlog 로 미룸(데스크톱 시간 보존).
- 화면은 EoY 와 같은 1280x720 landscape expand — 모바일에서 검증된 설정.

## 세션 3 — 횡스크롤 프로토타입 (백로그 1순위)
- `scripts/core/ExpeditionRun.gd` 신설 — 순수 전진/소모 로직. 물 1/걸음, 식량 1/2걸음, 물 0이면 갈증사.
  자원=수명. core/ui 분리 원칙대로 노드·렌더링 무의존(스모크: 물10 → 10걸음째 thirst, 식량 2 남음 PASS).
- `scripts/GameState.gd` — `current_run`(ExpeditionRun) 보유로 전환. `current_leg`/`carried` 제거.
  `begin_run_in_place()`(씬 전환 없이 런 생성) 분리 + `START_RESOURCES`(물10/식량7/로프1/은신처1).
- `scripts/ui/Expedition.gd` 전면 재작성 — `_draw`로 횡스크롤 단면 렌더(지면·걸음 눈금·걷는 이·과거 흔적 점),
  자원 HUD(물/식량 색상 경고), 터치 우선 큰 버튼(전진/끝), 소모 자원 0 시 자동 죽음 → 흔적 남김 → 지도.
  그림은 전부 `_draw`(셰이더/GPUParticles 없음, 웹 안전). 죽음 태그는 사인별 WordPool 어휘([갈증][끝] 등).

### 결정 (세션 3)
- **전진/소모 로직을 core 순수 클래스로.** Expedition.gd 은 렌더·입력만 — 페이싱 튜닝을 로직 단에서 테스트 가능하게.
- **횡스크롤을 _draw 로 직접 그림.** 에셋 없이 즉시 보고 튜닝, 웹 export 제약(셰이더/GPUParticles 금지) 자동 충족.
- **물/식량 두 시계, 다른 속도.** 물이 보통 먼저 바닥나는 긴급 시계. 수치는 임시 — 폰 테스트로 검증.
- 직접 진입 안전장치가 `_ready` 중 씬 전환 시 "parent busy" 에러 → 런 생성과 씬 전환 분리로 해결 (known_issues 등록).

## 세션 4 — 상황 읽기 (페이싱 결정 레이어)
- 페이싱 판정: 순수 전진 스팸은 결정이 0이라 단조롭다고 진단(기획서가 예고한 리스크). 사용자가 "상황 읽기"(This War of Mine 결) 선택.
- `scripts/core/Situations.gd` 신설 — 상황 카탈로그(순수 데이터) 4종: 틈(차단/로프), 마른 구간(소모), 폭풍 전조(폭풍/은신처),
  과거의 내 물통(소모/보충). 각 상황 = 읽기 + 2선택, 효과는 자원 델타. `needs` 로 대비 자원 부족 시 선택지 잠금.
- `scripts/core/ExpeditionRun.gd` — 3걸음마다 상황 세움(`pending_situation`), `apply_choice()` 로 효과 반영·고갈 재판정. RNG 시드.
- `scripts/ui/Expedition.gd` — 상황 결정 카드 패널(위협 라벨 + 본문 + 선택 버튼, 효과 힌트 "물 -2" 표시), 전진 중 상황 뜨면 결정 강제.
- 검증: 로직 스모크 5회 PASS — 선택에 따라 9~14걸음으로 갈리고, 한 판은 갈증이 아니라 배고픔으로 죽음(결정이 결과를 바꿈).

### 결정 (세션 4)
- **상황 규칙은 core, 카드 UI는 ui.** Situations(데이터)+ExpeditionRun(스케줄)이 규칙, Expedition.gd 은 표시만. 페이싱 수치를 로직 단에서 튜닝/테스트.
- **효과 = 자원 델타(즉시).** 지속 상태(갈증 지대 배수 등) 없이 단순화 — 프로토에서 페이싱 체감이 목적. 선택이 곧 죽음일 수도 있게.
