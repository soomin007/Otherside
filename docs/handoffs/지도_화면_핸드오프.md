# 지도 화면 디자인 핸드오프 — "See you on the other side"

> **용도:** 이 문서 하나만 보고 게임의 **지도 화면(계획 화면) 레이아웃·구성·시각 디자인**을 외부(Claude 디자인/아티팩트 등)에서 개선·재설계하기 위한 브리프. 코드 접근 없이도 이해되게 self-contained.
> **전반 UI 규칙(팔레트·타이포·컴포넌트)** 은 같은 폴더의 `UI_스타일_핸드오프.md` 와 함께 본다. 이 문서는 그중 **지도 화면 한 장**에 집중한다.
> **현재 모습:** 아래 스크린샷(데스크톱 1280×720). 실제 렌더본이다.

![현재 지도 화면](map_screen_current.png)

## 1. 게임이 뭔가 (한 문단)

비동기 로그라이트. 매년 재앙을 멈추러 **원정대가 사막으로 떠나고 거의 다 죽는다.** 플레이어는 그 원정대를 거듭 보내는 총괄자이자 매 원정의 대장. 모래폭풍이 글씨를 지우는 세계라 말은 안 남고 **물건만 남는다.** 정서는 **담담·서늘·쓸쓸함 + 릴레이의 옅은 희망.** 톤 레퍼런스 = 반지의 제왕 고지도 + 빛바랜 탐험 일지. (밝고 매끈한 앱 UI 아님.)

## 2. 지도 화면의 역할 (왜 이 화면이 있나)

코어 루프는 두 화면을 오간다: **계획(지도) ↔ 실행(도착 단면).** 이 문서는 **계획 화면**이다.

- **하는 일:** 낡은 양피지 지도 위에서 **다음에 갈 노드를 고른다.** 고르면 마커가 그 노드로 이동(자원 소모)하고, 도착하면 다른 화면(단면 탐색)으로 넘어간다.
- **강한 미지:** 가본 노드만 정체가 드러나고(장소 그림+이름), 갈 수 있는 다음은 "?", 그 너머는 안 보인다. 안개가 원정마다 걷힌다.
- **핵심 감성:** 액션이 아니라 **관리·판독·대비**. 지도를 들여다보며 "어디로 갈지" 고민하는 사색의 화면. 페이싱이 느긋해야 한다.

## 3. 현재 화면 구성 (스크린샷의 요소들)

위에서 아래로:
1. **상단 — 제목 "지도 · 탐험"** (중앙, H1) + 그 아래 **자원 HUD**("물 20 · 식량 13 · 로프 1 · 은신막 1").
2. **좌상단 — "기록" 버튼**(책갈피, 상시). **우상단 — "DEV"**(개발용, 정식 빌드엔 숨김 — 디자인 무시).
3. **가운데 — 양피지 지도(핵심).** 그을린 테두리의 낡은 종이. 위에:
   - **노드**(장소): 손그림 아이콘 + 이름. 마을→마른 강→버려진 야영지/오아시스→뼈의 들판→무너진 담/폭풍의 문→??? 로 **왼쪽에서 오른쪽으로** 이어진다(가지 분기 있음).
   - **길**: 노드를 잇는 세피아 잉크 곡선. 밟은 길=실선+발자국, 미지=점선. 갈림엔 실제 간 방향 화살표.
   - **원정대 마커**: 현재 위치(붉은 세피아 잉크 방울).
   - **나침반**: 좌하단(원본 이미지의 장식).
   - **지형지물**: 강·산·사구·폭풍·해골 등 원정대 손스케치(방문 구간에 나타남).
4. **하단 — 안내문**("갈 곳을 고르세요...") + **"남기기" 버튼**(물건 두고 가기) + **통계**("흔적 4개 · 죽은 자리 4곳 · 원정 8회").

## 4. 레이아웃 스펙 (지금 어떻게 배치되나)

- **논리 해상도 600×720, stretch `canvas_items`/`expand`.** → 데스크톱은 가로로 넓어지고(≈1280×720 논리), 폰은 세로로 길어진다. **한 레이아웃이 가로/세로 둘 다 대응(반응형).**
- **지도 영역 = 화면 창(제목·HUD 아래 ~ 하단 버튼 위)에 배경 이미지를 종횡비 유지로 온전히(contain) 넣은 rect.** 배경과 노드가 이 영역을 공유한다.
- **배경 이미지는 세로 원본(720×1280).** 폰(세로)엔 그대로, **데스크톱(가로)엔 90° 회전본(1280×720)** 을 쓴다(나침반이 방사대칭이라 회전 티 안 남).
- **그래서 데스크톱에선 지도가 화면 중앙에 가로 띠로 들어가고 좌우에 검은 여백이 남는다**(스크린샷 참고). 이 여백은 **의도적으로 비워둔 것** — §7 참고.
- 상/하단 고정 여백: 위 ~140px(제목+HUD), 아래 ~156px(안내+버튼+통계). 화면 가장자리 여백 32px.
- **노드 배치:** 진행축(가로=데스크톱)에 마을(0)~목적지(7)까지 8단계, 분기축(세로)에 갈래(col 0~1). 노드 아이콘은 노드 간격에 비례(안 겹치게).

## 5. 노드 그래프 (고정 데이터 — 바뀌지 않음)

지도의 **연결 구조·노드 개수는 게임 데이터라 고정**이다(디자인이 바꾸는 대상 아님). 총 11노드, row(진행) 0~7:

- row0 마을 → row1 마른 강 → row2 버려진 야영지 / 갈라진 바닥 → row3 오아시스 / 모래의 벽 → row4 뼈의 들판 / 독 웅덩이 → row5 무너진 담 → row6 폭풍의 문 → row7 ???(목적지).
- 각 노드는 `kind`(마을/보급/차단/폭풍/목적지)를 가지고, 그에 맞는 그림·심볼이 붙는다.
- **디자인이 다루는 건 "이 구조를 어떻게 보기 좋게 그리나"** — 노드 칩 스타일, 길 표현, 마커, 여백 활용, 전체 구성.

## 6. 비주얼 요소 (에셋 & 표현)

- **배경:** `01_지도_양피지.png`(720×1280, 그을린 테두리+나침반+양피지 결). 실제 이미지 에셋.
- **노드 아이콘:** kind별 손그림 장소 그림(마을·강·야영지 등) PNG. 방문한 노드만 표시.
- **지형지물:** 강/산/사구/폭풍/해골/경고/화살표 손스케치 PNG(세피아 펜). 경로 주변에 흩어짐.
- **길·마커·곡선·발자국·안개점·"?":** **전부 절차적 `draw_*`(코드로 그림)** — 이미지 아님. 세피아 잉크 톤.
- **아이템/자원 톤 이질:** 아이템·장소 아이콘은 사진풍인데 지형지물은 펜 스케치라 톤이 다르다(통일 여지 있음).

## 7. 디자인이 풀어줬으면 하는 것 (핵심 요청)

지금 골격은 돌아가지만, **더 예쁘고 완결된 계획 화면**을 원한다. 특히:

1. **★ 데스크톱 좌우 여백 활용.** 지금 가로 화면에서 지도 양옆이 검게 비어 있다. 여기에 게임 톤에 맞는 무언가를 채우고 싶다 — 예: **범례**(아이콘 뜻), **자원 상세 패널**, **원정 기록/통계**, **설정 버튼**, 또는 지도를 감싸는 **장식 프레임**(가죽/양피지 테두리로 여백을 메움). 무엇을 어떻게 배치할지 제안 환영.
2. **전체 구성·위계.** 제목·HUD·지도·버튼의 배치와 여백이 "낡은 탐험 일지"처럼 정갈한지. 지도가 주인공으로 부각되는지.
3. **노드/길 시각 스타일.** 노드 칩·이름 라벨·길 곡선·마커가 양피지 위에서 읽기 좋고 아름다운지. (가독성 + 분위기)
4. **여백/프레임 미감.** 지도 띠와 검은 배경의 경계, 그을린 가장자리 처리.

**폰(세로)도 잊지 말 것** — 세로에선 여백이 거의 없고 지도가 위→아래로 길어진다. 데스크톱 여백 UI는 세로에서 어디로 갈지(접기/하단 이동)도 고려.

## 8. 제약 (반드시 지킬 것)

- **엔진 Godot 4.6, 2D, GDScript. 웹 export + GL Compatibility + 모바일 터치 우선.**
- **셰이더·GPUParticles 금지**(웹에서 깨짐). 효과는 CPU/절차적/CPUParticles2D만.
- **에셋 경량.** 웹 빌드가 이미 무겁다. 새 텍스처는 작게·적게(9-patch·타일 권장).
- **한글 필수.** 모든 텍스트 한국어 → 폰트는 한글 글리프 포함(§UI핸드오프 §4). 장식 유니코드 금지.
- **터치 타깃 큼직**(버튼 60~76px), 여백 넉넉.
- **팔레트(양피지 표면):** PAPER `#D1BD91` · PAPER_EDGE `#947A52` · INK(세피아) `#45301C` · INK_FADE `#80694A` · 마커 `#8C331F`. UI 크롬: BG `#111218` · SAND(강조) `#D6B278` · FG `#EDEDF5`. (전체 표는 `UI_스타일_핸드오프.md §3`.)

## 9. 산출물 & 통합 방법 (뽑아온 걸 어떻게 붙이나)

지도 화면은 `scripts/ui/Map.gd` 에서 **절차적 `draw_*` + 이미지 에셋**으로 그린다. 그래서 받고 싶은 건:

- **레이아웃 목업/스펙** — 데스크톱·폰 두 폼팩터의 배치안(여백에 뭘·어디에). 치수·비율·계층. → 코드로 옮긴다.
- **여백 프레임/장식 PNG**(선택) — 지도를 감싸는 가죽/양피지 테두리, 코너 오너먼트. 9-patch면 흰 배경→투명 규칙 + 모서리 여백(px) 명시(§UI핸드오프 §7).
- **노드 칩·라벨·길·마커 스타일 가이드** — 선 두께·색·형태(절차적 draw 로 재현할 스펙).
- **범례/사이드 패널 디자인**(여백 활용안).

**형식:** "게임에 바로 꽂을 PNG 타일 + HEX + 치수" 가 SVG/피그마보다 통합이 빠르다. 순수 레이아웃 제안은 주석 달린 목업 이미지 + 수치표로.

## 10. 요약 한 줄

**"낡은 양피지 위의 원정 계획도"** — 세피아 잉크로 그린 노드·길, 그을린 종이, 좌하단 나침반. 데스크톱 가로 화면의 **비어 있는 좌우 여백을 게임 톤으로 채워** 지도를 한 장의 완결된 탐험 일지로 만드는 것이 핵심 과제. 구조(노드 그래프)는 고정, **시각 표현·레이아웃·여백 활용은 자유.**
