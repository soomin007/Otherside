# 밸런스 튜닝 노트 — 이어받기용

> **이 문서 하나로 밸런스 작업을 바로 이어간다.** 사용자가 "밸런스 이어서" 하면 여기부터.
> 도구: `tests/balance_sim.gd`(정량 시뮬), `scripts/ui/DebugOverlay.gd`(실기기 세팅). 실행법은 `00_START_HERE.md` §8.
> 이력: 2026-07-01 밤 도구 제작 + 첫 발견(end 도달 0%). **2026-07-02 1차 튜닝 — end 도달 0% → ~10% 확보**(아래 §달성).

## 어떻게 작업하나 (워크플로)

1. 손잡이 하나(또는 조합)를 바꾼다. 손잡이는 `ExpeditionRun` 의 **static var**(게임 기본값 고정, 시뮬만 오버라이드).
2. `godot --headless --path . -s tests/balance_sim.gd` 실행 → 리포트 비교.
   - `[1]` 정책 비교(생존탐욕/무작위/무모) · `[2]` 시작 물 스윕 · `[3]` **2D 스윕(DESO × EDGE_LEN, static var 오버라이드→원복)** · `[4]` 콘텐츠 커버리지.
   - 볼 것: **end 도달률**, 정책별 **중앙 leg**, **평균 최종 노드 row**, **사인 분해**(갈증/배고픔), **콘텐츠 커버리지**(0=못 봄).
3. `godot --headless --path . -s tests/core_smoke.gd` 로 회귀 없는지(ALL PASS) 확인.
4. 부팅 스모크 `godot --headless --path . --quit-after 5` (에러/경고 0).
5. 수치가 코드/기획서 양쪽에 있으면 **같은 커밋에서 둘 다** 갱신(기획서 §4.3 거리 곡선 등).
6. 실기기 체감은 DebugOverlay(자원 가득/노드 점프/God)로 원하는 지점만 띄워 확인.

⚠️ **시뮬 baseline 동기화:** `balance_sim.gd`의 `BASE_START` 는 `GameState.START_RESOURCES`(=Loadout 표준 구성)와 맞춰야 한다. 시작 자원을 바꾸면 둘 다.
⚠️ **손잡이 = static var:** `ExpeditionRun` 의 `WATER_PER_STEP`/`DESOLATION_EVERY`/`FOOD_EVERY`/`EDGE_LEN`/`GAP_*` 는 `const` 가 아니라 `static var`. 시뮬 `[3]` 이 값을 오버라이드하고 끝에 원복한다 — 게임 중엔 항상 기본값. (그래서 `[3]` 이 한 번의 실행으로 격자 스윕을 낸다.)

## 달성 (2026-07-02, 정책당 500판) — end 0% → ~10%

**사용자 결정:** 방향 = **보급 강화 (거리 유지)** / 목표 = **생존탐욕 단일 런 end 10~20%**(희소).
핵심 근거: 2D 스윕에서 `EDGE_LEN` 이 지배적 손잡이(EDGE 5 유지 시 DESO 28까지 올려도 <1%). 하지만 사용자가 **거리감(35걸음) 유지**를 택함 → `EDGE_LEN` 5 고정하고 **DESO 완화(걸음 수 불변, 후반 물 가속만 늦춤) + 후반 캐시 물 증량**으로 도달성 확보.

**적용:**
- `DESOLATION_EVERY` **16 → 30** — 후반 물 소모 누적 ~59 → ~41. `leg 30+` 에서만 2배 = 완주 마지막 ~5걸음이 가혹(거리 곡선 유지, 벽만 낮춤).
- **후반 캐시 물 증량(~+10, 초반 row 0~1 은 안 건드림 → 초반 긴장 유지):**
  · d1 뼈의 들판: `bones_gather` 물 2→3, `bones_flask` spot 물 2→3
  · e1 무너진 담: `wall_pack` spot 물 0→2(+식 2)
  · f1 폭풍의 문: `gate_relic` spot 물 2→4 ("앞선 이의 유품", 후반일수록 유품↑ 서사와 일치)
  · c2 모래의 벽: `wall_tarp` spot 물 0→2 (물 부족 경로 보강 — c1 오아시스 경로 대비 c2 폭풍 경로가 물 빈약해 절반이 여기서 죽던 비대칭 완화)
  · c1 오아시스: `oasis_edge` spot 물 2→3

**결과(EDGE 5 · DESO 30 기본값):**
- 생존탐욕 end **~10%**(중앙 28걸음) · 무모강행 **~0.2%**(스킬 격차 유지) · 무작위 0%.
- 사인 분해: **갈증 58 / 배고픔 33 / 위협 9** (이전 갈증 98% 독점 해소).
- 콘텐츠: f1 `storm_gate`·`storm_gate_eye`·`storm_gate_ill`(이전 전부 0)·후반 체인 `pool_drank→storm_gate_ill` **전부 활성화** — 죽은 후반 콘텐츠 해소(시뮬의 핵심 목적).

**여전히 0(단일 런 시뮬로는 원래 못 뜸):** `river_dug_again`·`camp_revisit_shelter`·`sand_wall_sheltered`·`bones_revisit_mourn` — 재방문 변형(영속 플래그 필요) 또는 탐욕이 안 고르는 선택이 켜는 체인. **다중 원정 시뮬(2단계, 미구현)** 영역.

## 다음 (폰 테스트 / 남은 튜닝)

1. **폰 실플레이로 정성 확인(긴장·페이싱·재미).** 시뮬 10%는 완벽 greedy 근사 — 실기기(사람)에선 더 낮을 수 있다. 체감 보고 미세조정(목표 대역 10~20% 안에서).
2. **배고픔 33% 재검토.** 갈증 독점은 풀렸으나 배고픔이 다소 높다. 취향이면 START 식량 or `FOOD_EVERY` 로 갈증/배고픔 비율 조정(예: 갈증 65/배고픔 25 목표).
3. **재회 임계 `REUNION_TRACES`(8) 튜닝.** end 도달이 열렸으니 이제 의미 있음. 재회는 end + 흔적 8 + 무사도달 셋 다 → 정확한 근거는 다중 원정 시뮬 필요.
4. **`EDGE_LEN` 다양화(엣지별 거리).** 현재 전 엣지 고정 5. 노드 간 실제 거리로 다양화하면 페이싱·거리감 개선 여지.

### 설계 의도 (놓치지 말 것)
- end/재회는 **어렵되 가능**해야 한다. 목표는 "높은 완주율"이 아니라 **여러 원정 축적 + 좋은 런이면 닿는** 정도(단일 런 end ~10%면 충분).
- 재회는 end 도달 **+ 흔적 8개 축적 + 무사 도달** 셋 다 → 단일 런 시뮬의 end 도달률은 필요조건일 뿐. 정확한 재회 경로는 **다중 원정 시뮬(2단계, 미구현)**로 봐야 한다.
- 거리 = 척박함의 기울기(기획서 §4.3)는 유지 — 후반이 가혹한 건 의도. DESO 30 은 벽을 낮췄을 뿐(마지막 5걸음 여전히 2배). "도달 불가"만 고쳤다.
